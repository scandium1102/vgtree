The operating loop

Map → Cover → Deepen → Prove

VGTREE makes breadth a real gate instead of a hopeful planning note. Deep work begins only when the required outcome surface is visible.

1

Map

A Capability Map names outcomes, dependencies, shared interfaces, risk owners, and final acceptance before implementation.

2

Cover

The Coverage Gate requires a minimum viable state and baseline evidence for every required branch.

3

Deepen

State 2.1 moves one way from WIDE to DEEP. A required policy blocks premature depth; an advisory override must disclose why.

4

Prove

Tool Receipts bind exact local bytes to compact evidence, while integration and final verification remain separate gates.

One product, two honest modes

Useful immediately. Deterministic when you need it.

The same schemas, templates, and contracts control both modes. Skills do not install software automatically.

ENGINE

Machine-enforced gates

A compatible local VGTREE 1.1 CLI validates maps, states, Coverage Gates, Receipts, and transitions. Only real machine evidence may support PASS.

SKILL_ONLY

Portable planning and review

Packaged references, schemas, and templates work without a preinstalled CLI. Reports disclose engine_validation=NOT_RUN, and overall status cannot exceed REVIEW_REQUIRED.

Six focused Skills

Load only the bundle the work needs.

The default Context Budget is one primary Skill plus at most one support Skill. Extra bundles need a reason and an unload condition.

ROUTER

using-vgtree

Classifies the task, chooses ENGINE or SKILL_ONLY, and loads the smallest useful workflow context.

PLAN

planning-tree-work

Builds the Capability Map, immutable branch contract, dependencies, risks, and acceptance matrix.

EXECUTE

executing-tree-work

Runs guarded branch work, records breadth coverage, and controls WIDE-to-DEEP progression.

VERIFY

verifying-tree-work

Checks branch evidence, integration, final verification, limitations, and inspectable Receipts.

ARCHITECT

governing-knowledge-architecture

Designs UID-first ownership, canonical roots, registries, provenance, lineage, and rollback boundaries.

OBSIDIAN

building-obsidian-workspaces

Audits or plans local vault structures and scaffolds only new or empty destinations.

Obsidian, first-class

Turn a vault into inspectable working memory.

VGTREE pairs execution trees with UID-first knowledge architecture. It can audit or plan an existing vault without rewriting notes, and scaffold only a new or empty destination.

  • Core mode: project UID, canonical owner/root, registry, Home, Map, Status, Todo, and rollback.
  • Governed mode: adds file UID, raw-byte SHA-256, provenance, lineage, journaled transactions, reference coverage, and readback.
  • Local boundary: VGTREE 1.1 does not apply, move, rename, rewrite, or delete files inside an existing vault.
vgtree obsidian audit --vault /notes --mode core

Trust boundaries

Evidence-backed does not mean evidence-blind.

VGTREE makes claims inspectable and keeps uncertain outcomes explicit.

No hosted control plane

No VGTREE account, hosted service, MCP server, telemetry, analytics, cookies, or remote font is required.

Structural validation

A valid map proves contract consistency, not that planning assumptions are true. A Receipt proves exact bytes and structure, not the producing tool’s honesty.

Separate completion gates

Baseline coverage cannot replace Definition of Done, integration, or final-verification evidence.

User-owned authority

External publication, destructive changes, accounts, payments, and identity verification remain explicit host and user decisions.

FAQ

Clear constraints, fewer surprises.

Is VGTREE another autonomous agent?

No. It is a portable workflow contract plus an optional deterministic Engine. The host agent still performs the work.

Does it need the CLI?

No. SKILL_ONLY works from packaged resources, but honestly stops at REVIEW_REQUIRED because Engine validation was not run.

Will it reorganize my vault?

Not in VGTREE 1.1. Existing Obsidian vault commands audit or create plans; scaffolding is limited to new or empty destinations.

Can I use it in my own program?

Yes. Call the JSON CLI out of process, consume the schemas, or package the Skills with a compatible host. VGTREE remains local-first and MIT licensed.
