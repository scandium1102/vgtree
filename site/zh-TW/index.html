核心循環

Map → Cover → Deepen → Prove

VGTREE 把「先顧廣度」變成真的 gate，而不是一張最後被遺忘的規劃表。必要成果面可見後，深層工作才開始。

1

Map

Capability Map 在實作前列出成果、依賴、shared interfaces、風險 owner 與 final acceptance。

2

Cover

Coverage Gate 要求每個必要分支都有 minimum viable state 與 baseline evidence。

3

Deepen

state 2.1 只允許從 WIDE 前進到 DEEP。Required policy 會阻止太早深挖；Advisory override 必須交代理由。

4

Prove

Tool Receipts 將本機精確 bytes 綁到精簡證據，同時保留獨立的 integration 與 final verification gates。

一個產品，兩種誠實模式

裝好 Skill 就能用；需要時再加入 deterministic Engine。

兩種模式共享同一套 schemas、templates 與 contracts。Skills 不會自動安裝軟體。

ENGINE

由機器執行 gates

相容的本機 VGTREE 1.1 CLI 會驗證 maps、states、Coverage Gates、Receipts 與 transitions。只有真實 machine evidence 才能支援 PASS。

SKILL_ONLY

可攜式規劃與審查

沒有預裝 CLI 時，仍可使用封裝的 references、schemas 與 templates。輸出必須標示 engine_validation=NOT_RUN，整體狀態最高只能到 REVIEW_REQUIRED。

六個專注的 Skills

只載入這次工作真正需要的 bundle。

預設 Context Budget 是一個 primary Skill，加上最多一個 support Skill。額外 bundle 必須說明理由與 unload condition。

ROUTER

using-vgtree

分類任務、選擇 ENGINE 或 SKILL_ONLY，並載入最小可用工作流 context。

PLAN

planning-tree-work

建立 Capability Map、immutable branch contract、依賴、風險與 acceptance matrix。

EXECUTE

executing-tree-work

執行 guarded branch work、記錄 breadth coverage，並控制 WIDE 到 DEEP 的前進。

VERIFY

verifying-tree-work

檢查 branch evidence、integration、final verification、limitations 與可檢查 Receipts。

ARCHITECT

governing-knowledge-architecture

設計 UID-first ownership、canonical roots、registries、provenance、lineage 與 rollback boundaries。

OBSIDIAN

building-obsidian-workspaces

審查或規劃本機 vault 架構，並且只在全新或空白目的地建立 scaffold。

Obsidian 是核心配套

把 vault 變成可檢查的 working memory。

VGTREE 把執行樹與 UID-first knowledge architecture 接在一起。它可以只讀審查或規劃既有 vault；scaffold 僅限全新或空白目的地。

  • Core mode：project UID、canonical owner/root、registry、Home、Map、Status、Todo 與 rollback。
  • Governed mode：再加入 file UID、raw-byte SHA-256、provenance、lineage、journaled transactions、reference coverage 與 readback。
  • Local boundary：VGTREE 1.1 不會在既有 vault 內 apply、move、rename、rewrite 或 delete 檔案。
vgtree obsidian audit --vault /notes --mode core

信任邊界

Evidence-backed 不等於看到證據就盲信。

VGTREE 讓 claim 可以被檢查，也讓不確定結果保持清楚。

沒有 hosted control plane

不需要 VGTREE 帳號、hosted service、MCP server、telemetry、analytics、cookies 或 remote fonts。

Structural validation

Map 合法只證明 contract 一致，不代表規劃假設為真；Receipt 證明精確 bytes 與結構，不替產生工具背書。

完成 gates 分開

Baseline coverage 不能替代 Definition of Done、integration 或 final-verification evidence。

授權由使用者持有

External publication、破壞性修改、帳號、付款與 identity verification 仍是 host 與使用者的明確決定。

FAQ

限制講清楚，工作比較不會走偏。

VGTREE 是另一個 autonomous agent 嗎？

不是。它是一套可攜式 workflow contract，加上一個選配 deterministic Engine；真正執行工作的仍是 host agent。

一定要有 CLI 嗎？

不用。SKILL_ONLY 可以直接使用封裝資源，但因為沒有執行 Engine validation，會誠實停在 REVIEW_REQUIRED。

它會自動整理我的 vault 嗎？

VGTREE 1.1 不會。既有 Obsidian vault 指令只做 audit 或產生 plan；scaffold 只限全新或空白目的地。

自己的程式可以呼叫嗎？

可以。程式可 out-of-process 呼叫 JSON CLI、使用 schemas，或把 Skills 包進相容 host。VGTREE 維持 local-first 與 MIT。
