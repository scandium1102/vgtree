# VGTREE v1.1 Coverage Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add state schema 2.1, computed breadth coverage, a one-way wide-to-deep transition, depth-aware guards, and CLI support while preserving schema-2.0 workflows.

**Architecture:** State schema 2.1 is opt-in when a compiled task contains `capability_map` with `ADVISORY` or `REQUIRED` policy. Coverage remains a substate of `branch_execution` and is computed from exact baseline evidence requirements. The engine, validator, Python API, CLI, and transactional store use one shared evaluator so a stored or caller-mutated state cannot bypass the gate.

**Tech Stack:** Python 3.10+, jsonschema Draft 2020-12, unittest, existing VGTREE engine and transactional StateStore

**Spec:** `docs/superpowers/specs/2026-08-20-vgtree-v1.1-coverage-evidence-design.md`

## Global Constraints

- Complete the Capability Map plan first.
- Schema 2.0 remains accepted and behaves as VGTREE 1.0.
- Schema 2.1 is emitted only for `ADVISORY` or `REQUIRED` maps.
- The seven workflow phases and existing branch/result states do not change.
- Baseline evidence never substitutes for final branch, integration, or final-verification evidence.
- A required deep transition is computed from current state, not a caller boolean.
- An advisory override requires a non-empty reason stored in coverage history.
- A high-risk `PRE_EXECUTION` owner remains a real dependency and is not delayed by breadth policy.
- All state mutations use the existing lock, validation, atomic write, and readback path.

~~~python
def _coverage_state_issues(state: dict[str, Any]) -> list[ValidationIssue]:
    version = state.get("schema_version")
    task = state.get("task")
    task_map = task.get("capability_map") if isinstance(task, dict) else None
    coverage = state.get("coverage")
    branches = state.get("branches")
    branch_items = branches if isinstance(branches, list) else []
    extended = any(
        isinstance(branch, dict)
        and any(field in branch for field in COVERAGE_BRANCH_FIELDS)
        for branch in branch_items
    )
    if version == "2.0":
        return [
            ValidationIssue(
                "STATE_VERSION_FEATURE_MISMATCH",
                "$.schema_version",
                "Schema 2.0 cannot contain Capability Map coverage fields.",
            )
        ] if task_map is not None or coverage is not None or extended else []
    if version != "2.1":
        return []
    issues: list[ValidationIssue] = []
    if not isinstance(task_map, dict) or not isinstance(coverage, dict):
        issues.append(
            ValidationIssue(
                "COVERAGE_STATE_REQUIRED",
                "$.coverage",
                "Schema 2.1 requires compiled map metadata and coverage state.",
            )
        )
        return issues
    if coverage.get("policy") != task_map.get("wide_pass_policy"):
        issues.append(ValidationIssue("COVERAGE_POLICY_MISMATCH", "$.coverage.policy", "Coverage policy must match the task."))
    if coverage.get("map_digest") != task_map.get("source_digest"):
        issues.append(ValidationIssue("COVERAGE_MAP_DIGEST_MISMATCH", "$.coverage.map_digest", "Coverage digest must match the task."))
    return issues
~~~

- [ ] **Step 3: Implement legal transitions**

`advance_execution_depth`:

1. validates state;
2. returns `COVERAGE_NOT_APPLICABLE` for 2.0;
3. requires phase `branch_execution` or returns `COVERAGE_PHASE_INVALID`;
4. returns `DEEP_STAGE_ACTIVE` if already deep;
5. evaluates current coverage;
6. blocks incomplete `REQUIRED`;
7. requires a stripped advisory reason when incomplete;
8. deep-copies state and writes exactly one coverage history entry;
9. sets `advanced_at` to the same timestamp;
10. returns `PASS / DEEP_STAGE_ACTIVATED`.

- [ ] **Step 4: Extend guard without changing 2.0 behavior**

For 2.0, `depth` remains optional and existing checks run unchanged. For 2.1:

- missing depth returns `FAIL / DEPTH_REQUIRED`;
- depth outside `wide` or `deep` returns `FAIL / DEPTH_INVALID`;
- `deep` while stage is `WIDE` returns `BLOCKED / DEEP_STAGE_NOT_ACTIVE`;
- then existing blocked, deferred, dependency, and primary-first checks run.
