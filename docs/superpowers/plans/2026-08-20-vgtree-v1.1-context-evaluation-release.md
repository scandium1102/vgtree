# VGTREE v1.1 Context, Evaluation, and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate Capability Map, Coverage Gate, Receipts, and Context Budget into the existing six Skills; add deterministic and behavioral evaluation contracts; update public documentation and version metadata; and produce release evidence without performing an unapproved external publication.

**Architecture:** VGTREE keeps six stable top-level Skills. Planning, execution, and verification Skills gain the new commands and exact gate semantics; Context Budget remains a host-facing operating policy, not an engine service. Deterministic fixture validation is a release gate. Model-dependent evaluations produce disclosed artifacts but do not become universal product claims. Release preparation stops before push, tag, GitHub release, or Plugin Directory submission until the owner explicitly approves each external effect.

**Tech Stack:** Markdown Agent Skills, JSON fixtures, Python 3.10+ standard-library validation script, unittest, setuptools build, official Plugin and Skill validators, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-20-vgtree-v1.1-coverage-evidence-design.md`

## Global Constraints

- Complete and independently review the Capability Map, Coverage Gate, and Receipts deliveries first.
- Keep exactly six plugin Skills; do not create separate `vega-capability-map` or `vega-tree-delivery` products.
- Default Context Budget is one primary bundle plus at most one support bundle.
- Additional bundles require a named reason and unload condition.
- T4, mixed-domain, and explicit audit work can exceed the default budget.
- Behavioral results disclose exact model, provider, date, reasoning setting, tools, trial count, fixture digest, and artifact references.
- Do not claim a fixed token or quality improvement from another project's benchmark.
- Core remains local-first, no-network, no-telemetry, and framework-neutral.
- Website authentication reported by the owner is `AVAILABLE` only; it is not submission authorization or successful-submission evidence.
- Push, tag, GitHub release, and Plugin Directory submission require explicit owner approval and authoritative readback.
