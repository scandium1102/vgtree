# VGTREE v1.0 Implementation Plan

> Execution rule: implement each behavior with a failing test first, observe the expected failure, then add the smallest production change that passes it.

Date: 2026-08-20
Target branch: `codex/vgtree-productization`

## Task 1: Repository and packaging baseline

Create the Python `src` layout, package metadata, license, initial public documentation, ignore rules, and CI skeleton. Add a smoke test that first fails because `vgtree` is not importable, then implement the minimal package and version export.

Acceptance:

- Editable installation succeeds.
- `python -m vgtree --help` exits successfully.
- Package version is `1.0.0`.

## Task 2: Strict models and state schema

Write regression tests for invalid task signals, nested unknown fields, invalid priorities, dangling dependencies, self-dependencies, cycles, and evidence-free accepted limitations. Implement typed models, JSON Schema 2.0, and semantic validation.

Acceptance:

- Every reproduced schema defect has a regression test.
- The schema is Draft 2020-12 valid.
- Unknown nested properties are rejected.

## Task 3: Classification and specialized routing

Write failing tests proving migration, project-scale, external-effect, and destructive signals cannot be downgraded by an explicit lower class. Add structured specialized-match tests, including an unknown workflow reference. Implement deterministic classification and a registry-backed match check.

Acceptance:

- Explicit classes only raise the computed class.
- Unregistered or partial specialized matches never route as specialized.
- T2-T4 unmatched tasks route to Tree execution.

## Task 4: Engine state machine and gates

Write failing tests for illegal phase jumps, premature completion, missing evidence, unsatisfied dependencies, blocked branches, accepted limitations, and valid completion. Implement initialization, legal transitions, branch selection, computed guards, validation, and completion.

Acceptance:

- Completion cannot occur before verification.
- Gates are computed from state and evidence.
- Results use stable status and code values.

## Task 5: Atomic persistence and locking

Write tests for atomic save/readback, collision handling, non-overwrite migration, malformed state, and stale lock behavior. Implement state storage with sibling temporary files, `os.replace`, and exclusive locks.

Acceptance:

- Concurrent mutation attempts return `BLOCKED`.
- Failed writes do not corrupt the previous state.
- Old-format migration never overwrites its source.

## Task 6: CLI contract

Write subprocess tests for every core command, JSON envelopes, standard input errors, and exit codes 0-3. Implement `classify`, `init`, `next`, `guard`, `validate`, `complete`, and `migrate-state`.

Acceptance:

- CLI output is valid JSON on success and controlled failure.
- No user error produces a traceback.
- Help text documents the local-first and no-telemetry behavior.

## Task 7: Obsidian architecture layer

Write filesystem tests for Core and Governed audit rules, plan generation, empty-destination scaffold, non-empty destination rejection, and unavailable live validation. Implement read-only audit/plan and safe scaffold commands.

Acceptance:

- Existing vault files are never modified.
- Scaffold rejects non-empty destinations.
- Starter templates open as valid Markdown/YAML and expose Home, Map, Status, Todo, and registry surfaces.

## Task 8: Build and evaluate six skills

For each skill, run a baseline agent scenario without the skill, record the failure or weaker behavior, write the skill, rerun the same scenario with the skill, and refine until the expected behavior is reliable. Do not batch-author all six without individual evaluation.

Acceptance:

- All six skills contain valid frontmatter and concise trigger descriptions.
- Skill-specific evaluations and expected outputs are committed.
- Skills use the CLI/API rather than duplicating engine logic.

## Task 9: Package the OpenAI plugin

Write manifest and layout tests first. Add the nested skills-only plugin manifest and repository marketplace manifest. Verify installation from the local repository.

Acceptance:

- Plugin declares skills only.
- All six skill paths resolve.
- Manifest fields pass the current official specification.

## Task 10: Public documentation and examples

Add English canonical documentation, Traditional Chinese quick start, architecture guide, UID modes, Obsidian guide, examples, migration guide, contribution guide, security policy, privacy policy, terms, support policy, and changelog.

Acceptance:

- A new user can install, classify, initialize, validate, and scaffold without private context.
- No deployment-private path, project, UID, or personal information appears in public artifacts.

## Task 11: Verification and release hardening

Run the full test suite, package build, artifact inspection, clean-room install, CLI smoke tests, skill evaluations, plugin checks, dependency audit, secret scan, private-context scan, and code review. Fix every blocking finding and rerun fresh verification.

Acceptance:

- All required checks pass from a clean environment.
- No high-severity security or privacy finding remains.
- Release evidence records exact commands and results.

## Task 12: GitHub release

Review the exact staged diff, create clean commits, publish `scandium1102/vgtree`, push the product branch, merge through the selected release path, tag `v1.0.0`, and create the GitHub release with verified artifacts.

Acceptance:

- Public repository and tag are readable anonymously.
- Release documentation URLs resolve.
- Installation from the public tag succeeds in a clean environment.

## Task 13: OpenAI Plugin Directory submission

Recheck the current official submission requirements, verify developer identity and Apps Management permissions, run plugin submission validation, and submit the GitHub-backed plugin. Record any review-only external gate precisely.

Acceptance:

- Submission is either confirmed with evidence or explicitly `BLOCKED` on a named account/review prerequisite.
- No review or publication state is claimed without readback.

## Task 14: V2 Vault registration and private adapter pointer

Only after the currently dirty V2 registry authorities are reconciled, allocate the next live project UID, create the VGTREE project control surfaces, update registries and discoverability, and add a private adapter pointer without copying private rules into the public repository.

Acceptance:

- Registry allocation comes from fresh live state.
- Transaction, hash, reference, and readback gates pass.
- The public repository remains free of private Vault data.
